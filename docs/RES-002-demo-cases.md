# RES-002：Demo 场景方案（赛博乐高 = 拼一个世界）

- 日期：2026-10-11
- 性质：调研 + 方案提案，供负责人挑选。参照 RES-001（乐高）与 INT-001。

## 0. 先想清楚：拼世界和拼积木有什么不同

乐高的乐趣在**零件之间的关系**，比如一块扣上另一块。我们拼的单位是"物件"而不是零件，所以乐趣要放在**物件与物件、物件与世界之间的关系**上。

可借鉴的对标（[Scribblenauts](https://en.wikipedia.org/wiki/Scribblenauts)、[Toca Boca](https://www.tocaboca.com/kids/toca-boca-world)）：

| 对标 | 它的做法 | 对我们的意义 |
|---|---|---|
| Scribblenauts | 写下什么就召唤什么；物件有共享属性（会飞、怕水、能吃），组合起来会产生没人专门写过的互动 | 给素材打上少量**属性标签**，世界就能"自己发生事情" |
| Toca Boca | 像数字玩具屋：没有分数、没有失败，孩子自己演故事 | 世界负责好玩，故事交给孩子 |
| Minecraft | 规则少而统一，玩家组合出无限可能 | 我们的"零件系统"= 素材库 + 关系规则 |

儿童假想游戏里反复出现的主题有：冒险寻宝、海盗/恐龙/太空、开店做饭、动物和家、超级英雄（[Natural Child Project](https://www.naturalchild.org/articles/research/ages_stages.html)、[Child Mind Institute](https://childmind.org/article/the-power-of-pretend-play-for-children/)）。6–9 岁孩子会构建复杂、多角色的假想世界。

**所以一个好的 demo 场景要同时满足四点：**
1. **世界级**：至少 3 个物件形成空间关系（旁边、上面、对岸）。
2. **会反应**：放进去的东西会互相影响，这是"咔哒"一声的替代品。
3. **可修改**：至少一次"不对，要……"。
4. **有人看**：最后能当导游讲给别人听。

## 1. 推荐方案：三幕，同一座岛

三个场景演在**同一座岛**上，依次展示 INT-001 的三层价值：**我创造 → 世界会回应 → 我和别人一起玩**。评委会看到世界在积累，这本身就是"持续回来"的证据。

### 场景一：把真实的一天搭出来——"外婆家门口的小河"

**展示的价值**：真实经历和想象放在同一个世界；归属感；说清楚就会更像。

**脚本**（约 30 秒）：
1. 孩子："今天我去外婆家了，外婆家门口有一条小河。" → 一座小房子落下，旁边一条小河蜿蜒出现。
2. 孩子："河里有好多小鱼，还有一只鸭子。" → 鱼跳出水面，鸭子在河上游。
3. 修改："房子要红色的屋顶！" → 屋顶变红，弹一下。
4. 想象加入："河对面要有一座糖果山。" → 糖果山在对岸长出来。

**抓眼球的点**：真实和想象隔着一条河，同框出现。观众会自然地问"那怎么过去？"，这就引出场景二。

**世界关系**：房子在河边，鸭子在河里，糖果山在对岸。

### 场景二：世界自己发生事情——"下雨了 / 天黑了"

**展示的价值**：世界会回应；物件之间的涌现互动；孩子用"规则"而不是"零件"在搭建。这是和"AI 生成一张图"拉开差距的关键一幕。

**脚本**（约 30 秒）：
1. 孩子："下雨了！" → 雨落下，鸭子开心地扑腾，小狗跑到房子屋檐下躲雨，河水涨了一点。
2. 孩子："雨停了，出彩虹。" → 彩虹从糖果山架到外婆家，**彩虹变成了桥**。
3. 孩子："天黑了。" → 天色变暗，房子窗户亮灯，糖果山发出微光。
4. 小居民提问（INT-001 的待验证功能）：鸭子说"好黑呀，我找不到家了"。孩子："给它一盏小灯笼！" → 河边亮起灯笼。

**抓眼球的点**：没人说"小狗去躲雨"，它自己去了。观众会意识到这是一个**活的世界**，不是素材拼贴。

**实现要点（6 小时可行）**：不用物理模拟，只用 4–5 条硬编码规则：
- 天气 `rain` → 带 `animal` 标签且不带 `likesWater` 的物件移动到最近的 `shelter`。
- `rain` → 带 `likesWater` 的物件播放开心动画。
- `night` → 带 `light` 标签的物件发光。
- `rainbow` 若两端都有物件 → 生成桥并连通。

### 场景三：在自己的世界里玩，然后当导游——"给小动物开一场派对"

**展示的价值**：已有作品产生新玩法（G2）；孩子决定故事；邀请家人（G4）。

**脚本**（约 30 秒）：
1. 孩子："今天是小狗的生日，大家都来糖果山开派对！" → 鸭子、鱼（跳出水面）、小狗沿彩虹桥走向糖果山，山顶出现蛋糕和彩旗。
2. 孩子："蛋糕上要有五根蜡烛。" → 蜡烛点亮。
3. 切换导游模式：鹈鹕载着镜头从外婆家沿着桥飞到糖果山，孩子边飞边讲："这是外婆家，这是我给小鸭子的灯笼……"
4. 屏幕角落浮出家长视角的一句话，是作品集而不是报告："这座岛有 3 天的故事：外婆家（第 1 天）、彩虹桥（第 2 天）、小狗生日（第 3 天）。"

**抓眼球的点**：前两幕搭的东西全都被"用上"了，桥用来走路，糖果山用来开派对。这正是乐高"拆了重搭、越积累越有用"的数字版本。

### 三幕串起来的评委叙事

> "乐高让孩子用手拼零件；我们让孩子用嘴拼世界。第一幕：孩子把真实的一天搭进来。第二幕：世界自己活了。第三幕：搭过的一切变成新的玩法，最后孩子带家人参观。故事只能由孩子讲，AI 只负责让它变成真的。"

## 2. 备选场景（可替换任意一幕）

| 场景 | 一句话 | 亮点 | 风险 |
|---|---|---|---|
| **恐龙要过河** | "恐龙想去对岸吃苹果树，但是河太宽了" → 孩子决定搭桥、造船还是让鸟驮它 | 一个问题多种解法，Scribblenauts 式；男孩向主题 | 需要"过河"判定逻辑 |
| **海底小镇** | 孩子把岛的一半变成海底，章鱼开面包店，鲨鱼当邮递员 | 场景切换视觉冲击大；职业扮演 | 需要水下素材和滤镜 |
| **我的动物园/宠物医院** | 孩子安排每只动物住哪里、吃什么，生病的小兔被送去医院 | 照顾类、关怀价值强；女孩向主题 | 偏模拟经营，容易变成任务 |
| **四季** | "变成冬天" → 河结冰、动物戴围巾、树变白，可以在冰上滑 | 一句话改变全岛，最强的"世界级"反馈 | 需要每个物件都有冬季变体 |
| **把梦搭出来** | "我昨晚梦见会飞的鲸鱼" → 鲸鱼在岛上空游 | 情感共鸣强，路演有故事感 | 单个物件，世界关系弱 |

**推荐的替换顺序**：如果"天气规则"做不完，场景二换成"恐龙要过河"（只需一条规则）；"四季"是最强的视觉备选，但素材量最大。

## 3. 素材与规则清单（按推荐三幕）

- **物件（约 15 个）**：房子、小河/池塘、鱼、鸭子、小狗、树、糖果山、彩虹/桥、灯笼、蛋糕、彩旗、蜡烛、鹈鹕、云/雨、月亮。均可在 Kenney / Quaternius 的 CC0 素材中找到近似件，糖果山可用彩色山体换材质。
- **属性标签（5 个）**：`animal`、`likesWater`、`shelter`、`light`、`walkable`。
- **世界状态（3 个）**：天气（晴/雨/彩虹）、时间（白天/夜晚）、事件（派对）。
- **预录兜底**：三幕都准备好每一句话对应的场景清单 JSON，现场语音识别失败时可以一键回放，不影响演示。

## 4. 需要负责人决定的

1. 三幕都用同一座岛？（推荐：是，因为积累本身就是卖点。）
2. 场景二的"小居民提问"要不要上？它与 INT-001 的"AI 主动程度"待决问题相关。（推荐：只上一次，并且只提问题不给答案。）
3. 演示台词由评委来说，还是由我们扮演孩子说？（推荐：第一幕由我们演，后两幕邀请评委说一句，提高参与感。）
